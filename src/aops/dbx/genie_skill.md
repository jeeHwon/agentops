# aops: 에이전트 점검·등록·평가·배포

PC의 `aops` 명령과 똑같은 것을 이 노트북에서 실행한다. 같은 aops 패키지, 같은 aops 서버 API, 같은 출력이다. 등록·검사·승인·배포는 aops 서버와 Job이 하고, 이 노트북은 요청한 사람의 권한으로 명령만 보낸다.

## 순서

1. **대상을 정한다.** 스킬·코드 기반은 에이전트 폴더다: 사용자가 말한 폴더, 아니면 지금 연 파일·노트북이 있는 폴더부터 위로 올라가며 `aops.toml`이 있는 폴더. 노코드(Genie)는 폴더 없이 에이전트 이름으로 `--agent <이름>`을 붙인다(아래 표). 하나로 정해지지 않으면 사용자에게 묻는다.
2. **aops 코드.** PC의 `aops` 명령과 같은 코드가 `__SRC__/aops`에 있다(읽기만). 설치하지 않고 이 폴더를 `sys.path`에 넣어 쓴다. 명령이 하는 일은 `aops/lifecycle.py`(`cmd_register`·`cmd_deploy`)와 `aops/client.py`(서버 호출)에서 확인할 수 있다.

3. **명령을 실행한다** (Python 셀 하나). `<에이전트 폴더>`와 명령만 바꾼다:

   ```python
   import os, sys
   sys.path.insert(0, "__SRC__")
   os.environ["AOPS_APP"] = "__APP__"
   os.chdir("<에이전트 폴더>")
   from aops.cli import main
   main(["register", "--bump", "minor"])
   ```

   | 사용자 요청 | `main([...])` |
   | --- | --- |
   | 셀프 체크 (형식만, 기록 안 함) | `["validate"]` · 노코드 `["validate", "--agent", "<이름>"]` |
   | 등록 (버전 폭: fix·minor·major, 말하지 않으면 minor) | `["register", "--bump", "minor"]` (노코드는 등록이 없다: 배포가 성공할 때 버전이 생긴다) |
   | 평가 (배포 전 Gate: 형식 + 평가셋·벤치마크, 기록) | `["evaluate"]` · 노코드 `["evaluate", "--agent", "<이름>"]` |
   | 배포 (버전을 말하지 않았을 때: 최신 버전) | `["deploy"]` · 노코드 `["deploy", "--agent", "<이름>"]` (지금 개발용 정의를 스냅샷으로) |
   | 버전을 말한 배포·되돌리기 | `["deploy", "--version", "1.0.0"]` (이유를 말했으면 `"--reason", "<이유>"`도, 노코드는 `--agent`도) |
   | 진행 중인 배포 요청 취소 | `["deploy", "--cancel"]` (노코드 `--agent`도) |
   | 권한 주기·회수 | `["promote", "<이름>", "--to", "group:<그룹>"]` (회수 `"--revoke"`. user:<이메일>·sp:<ID>도) |
   | 에이전트 목록·운영 버전 | `["list"]` |
   | 내 배포 요청 | `["gates", "--mine"]` |

   사용자가 버전을 말했으면 반드시 `--version`으로 그 버전을 넣는다. 이유는 묻지 않아도 된다(선택).

   각 명령이 하는 일 (실행 전에 사용자에게 한 줄로 알린다):
   - `validate`: 폴더(노코드는 개발용 Genie)의 형식을 지금 바로 점검한다. 아무것도 기록하지 않는다.
   - `register`: 폴더를 zip으로 묶어 aops 서버에 올린다. 서버가 레지스트리에 새 버전을 기록한다. 운영에는 반영하지 않는다.
   - `evaluate`: 서버가 평가 Job으로 형식을 다시 검사하고 품질을 평가한다(스킬: 평가셋 질문을 모델이 답하고 채점, 노코드: Genie 벤치마크). 결과가 레지스트리에 남고, 같은 내용으로 배포를 요청하면 이 결과를 쓴다.
   - `deploy`: aops 서버에 배포 요청을 보내고 진행을 보여 준다. 서버가 평가 Job → 승인(정책) → 배포 순서로 운영 버전을 바꾼다. 이 노트북은 노트북·Job·파이프라인·권한을 바꾸지 않는다.
   - `promote`: 운영 대상(스킬 UC Skill·코드 앱·노코드 운영용 Genie)에 대상자 권한을 준다. 담당자·담당 팀만 된다.
   - `deploy --cancel`, `list`, `gates`: 요청을 취소하거나 읽기만 한다.

4. **셀 출력을 그대로 보여 준다.** 실패하면 출력에 나온 이유와 다음에 할 일을 짧게 덧붙인다.

## 지키는 것

- 위 `aops` 명령만 쓴다. aops 서버를 직접 부르거나, 레지스트리 테이블·볼륨에 쓰거나, 에이전트 파일을 고치지 않는다.
- 토큰을 출력하거나 저장하지 않는다.
- 승인·반려는 승인자가 한다. 요청한 사람을 대신해 `approve`를 실행하지 않는다.
- 배포는 운영에 반영되는 일이다. 사용자가 배포를 요청했을 때만 `deploy`를 실행한다. 권한도 사용자가 대상을 말했을 때만 `promote`한다.
